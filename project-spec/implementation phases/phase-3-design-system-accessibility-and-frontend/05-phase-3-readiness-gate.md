# Phase 3.5 — Phase 3 Readiness Gate

## Role

You are the frontend acceptance gate reviewer.

## Prerequisites

Review Phase 3.1–3.4, Phase 1 frontend specification/route map, Phase 2 PASS and all test/review evidence.

## PASS criteria

Issue **PHASE 3: PASS — PROCEED TO PHASE 4** only if all approved routes render; homepage/article/listing/static/search-if-approved/RSS/sitemap/404 behavior is evidenced; navigation/footer work by keyboard and mobile; visual review follows `frontend.png`; accessibility/image/performance blockers are resolved; content logic is separate; checks pass; no Work scope exists.

## BLOCK criteria

Issue **PHASE 3: BLOCK — DO NOT PROCEED TO PHASE 4** for missing routes, keyboard/accessibility blockers, major design divergence, failed checks, collisions or scope leakage.

## Required deliverable

Create a dated evidence-backed gate record with reviewer, checks, blockers/remediation owners and next action. A PASS authorizes CMS/schema work, not bulk migration.
