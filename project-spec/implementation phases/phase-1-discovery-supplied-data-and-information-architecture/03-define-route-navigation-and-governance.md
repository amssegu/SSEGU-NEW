# Phase 1.3 — Define Route, Navigation and Content Governance

## Role

You are the information-architecture and editorial-governance lead.

## Prerequisite

Phase 1.2 inventories and exception reports must exist. Read the route requirements in `techspec.md`.

## Objective

Convert audited data into an approved route map, navigation model, internal-linking rules and content-governance specification.

## Required work

1. Define routes for homepage, news/listing, categories, articles, approved search, static pages, RSS, sitemap, admin and 404.
2. Resolve or disposition preserved URLs, slug collisions, redirects, 404/410 cases and manual-review routes.
3. Define main-site header/footer navigation, category visibility, ordering and internal-linking rules.
4. Record search inclusion as an explicit decision, and keep navigation data separate from presentation where useful.
5. Define required fields, publication status, author/category ownership, sponsored-content labels, image standards, captions, credits and alt text.
6. Define portable content rules and exclude Work/job/internship/course/employer collections.

## Deliverables

- Approved route map.
- Navigation/internal-linking specification.
- Route disposition and unresolved-route register.
- Content-model/editorial-governance document.

## Validation and handoff

Every launch route has an owner and acceptance rule; route decisions are evidence-backed; search is approved or explicitly excluded; no Work scope is introduced. Phase 2 can proceed without inventing URL or editorial rules.
